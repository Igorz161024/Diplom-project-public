# Моя ERP система на PostgreSQL

## Вступ
Моя ERP система на PostgreSQL відрізняється від Oracle чи Microsoft Dynamics тим, що є навчальним і практичним проєктом, який дає мені повне розуміння бухгалтерії та аналітики, тоді як комерційні продукти орієнтовані на корпорації й коштують дорого.  

У своїй дипломній роботі я досліджую ERP системи як ключовий інструмент сучасного бізнесу. ERP (Enterprise Resource Planning) дозволяє інтегрувати фінанси, бухгалтерію, складський облік, виробництво та продажі в єдину базу даних, що забезпечує цілісність інформації та оперативність прийняття рішень.  
Метою моєї роботи є створення навчальної ERP системи на базі PostgreSQL, яка моделює бізнес‑логіку та демонструє роботу бекенду.  

---

## Аналітична частина
Порівнюючи ERP системи з програмним продуктом 1С, я доходжу висновку, що 1С є локалізованим рішенням, орієнтованим переважно на бухгалтерський та податковий облік у країнах СНД.  
Класичні ERP системи (SAP, Oracle, Microsoft Dynamics) охоплюють значно ширший набір бізнес‑процесів: фінанси, виробництво, логістику, управління персоналом та аналітику.  

Моя ERP система на PostgreSQL поєднує простоту та доступність 1С із системністю західних ERP.  
- Орієнтована на індивідуальне використання та навчання.  
- Функціональність формується поступово, залежно від потреб.  
- Архітектура базується на локальній базі PostgreSQL та FastAPI, з можливістю розгортання у Docker.  
- Використовує безкоштовні технології з відкритим кодом (PostgreSQL, Python).  
- Аналітика реалізується через SQL, Pandas та потенційну інтеграцію з BI сервісами.  

---

## Практична частина
- SQL схема бази даних PostgreSQL: клієнти, постачальники, товари, продажі, проводки.  
- ORM SQLAlchemy для зв’язку між Python‑кодом та БД.  
- FastAPI бекенд з REST‑ендпоінтами для роботи з даними.  
- Docker Compose для запуску контейнерів (backend, frontend, db, backup).  
- Swagger UI для тестування API.  

### Бухгалтерська логіка
Реалізовано принцип подвійного запису (дебет/кредит) через таблиці `accounts` та `journal`. Це відповідає міжнародним стандартам (IFRS, GAAP).  

### Інфраструктура та перспективи
- Використання Nginx як реверс‑проксі.  
- Можливість масштабування через Kubernetes.  
- Подальший розвиток: BI аналітика, мультивалютність, багатомовність.  

---

## Висновки
Я створив навчальну ERP систему, яка відтворює основні принципи великих комерційних продуктів, але залишається гнучкою та адаптованою для практичного використання у навчальному середовищі.  
Цей дипломний проєкт перетворюється на реальний бекенд‑стек, який може бути використаний як демонстраційна платформа для викладачів та студентів, а також як приклад моїх професійних навичок для роботодавців.  
Система успішно запускається на чистій системі (WSL/Windows) та проходить тестування API і фронтенду.

## Еволюція системи (результати з CHANGELOG)
### Базові кроки (березень 2026)
- Перехід на PostgreSQL 18.3, налаштування volume та інтеграція FastAPI.  
- Додано `.env.dev` та `.env.prod` для безпечного збереження конфігурацій.  
- Усунуто проблеми з Docker, відновлено роботу ендпоінтів FastAPI.  
- Інтегровано React‑фронтенд, створено нові компоненти для бухгалтерії та HR.  

### Розвиток архітектури (квітень 2026)
- Налаштовано JWT‑автентифікацію для різних ролей (Finance, HR, Admin, Products, PKash, Inventory, Purchases, Sales, Legal).  
- Додано компонент JournalTable у фронтенді.  
- Виправлено CORS у FastAPI, налаштовано nginx для SPA‑маршрутів.  
- Створено модулі Finance, HR, Admin, Products, PKash.  
- Реалізовано базові роутери FastAPI для Finance, Inventory, Purchases, Sales, Legal.  

### Завершення CRUD та інтеграція (травень 2026)
- Додано резервне копіювання бази даних через `backup.sh`.  
- Запущено модуль Journal, інтегровано фронтенд із бекендом.  
- Реалізовано повний CRUD для Journal та Finance.  
- Виправлено циклічні імпорти у моделях, переписано схеми Journal та Finance.  
- Перевірено фінансові ендпоінти `/add_entry`, `/balance`, `/report`, `/plot`.
